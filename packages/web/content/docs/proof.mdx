## The setup check, measured

The first two reports are the same agent, the same 40 invoices and the same model. The only change is where the supplier data sits.

- Before: the setup check flagged "Data sits inside the system prompt". The evidence it gave was one block, `SUPPLIER BOOK (json, 7342 characters)`, in a 21,337-character system prompt. SERV plain scored 27 of 40, 67.5%.
- The one-click fix moved that block into shared data, which travels in the user message. The system prompt dropped to 13,979 characters.
- After: SERV plain scored 39 of 40, 97.5%.

What the check looks for and how the fix works is on [Setup check](/docs/concepts/setup-check).

## The prove command

One command runs Urai end to end over HTTP against a running server and prints PASS or FAIL per step.

```bash
cd packages/web
npm run prove
```

It talks to `http://localhost:3101` by default. Point it elsewhere with `npm run prove -- --base https://your-host`. The base must be https, or http on localhost, because a key rides on these calls.

It spends real money, about 0.05 USD, and stops sending new calls before the spend would pass 0.10 USD. It uses the operator key from the root `.env`.

| Step | What it does | What must hold |
|---|---|---|
| 1 | `GET /api/models` | The list is not empty, is verified live from SERV, and includes `gpt-6-luna` |
| 2 | `POST /api/lint` on the bad-layout sample | A "data in the system prompt" finding comes back, with a one-click fix |
| 3 | A team run on the fixed workload's first 10 cases, SERV off and SERV plain | The spend from SERV's token counts stays under the cap, and all 20 calls come back |
| 4 | A demo run on `sample-invoices-good`, no key | The run holds exactly 12 cases, all 24 calls come back, and the report carries no balance reading |
| 5 | Share the demo run, then fetch it by report id with no header | The public report has the same totals as the owner's, and the run id appears nowhere in it |

The last lines print the estimated spend and `RESULT: PASS (5 of 5 steps)`, or FAIL with the count. Any failed step makes the command exit with code 1.
